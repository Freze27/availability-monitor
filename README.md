# Availability Monitor

REST API для мониторинга доступности HTTP и HTTPS-ресурсов. Сервис хранит список адресов и проверяет их автоматически, каждый по своему интервалу, или вручную по запросу. Результаты проверок сохраняются в историю, при падении и восстановлении адреса фиксируются события, а по истории можно получить сводку за период.

## Запуск

Требуется Go 1.27 или новее и Docker для базы данных PostgreSQL.

Создайте файл `.env` из образца `.env.example`:

```bash
cp .env.example .env
```

Установите зависимости, запустите базу данных и приложение:

```bash
go mod download
docker compose up -d postgres
go run ./cmd/monitor
```

Сервис доступен по адресу `http://localhost:8080`.

## API

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/health` | Проверка, что сервис жив |
| `POST` | `/targets` | Добавить адрес |
| `GET` | `/targets` | Список адресов с последней проверкой |
| `GET` | `/targets/{id}` | Получить адрес |
| `PATCH` | `/targets/{id}` | Изменить адрес, поставить на паузу или снять с паузы |
| `DELETE` | `/targets/{id}` | Удалить адрес вместе с его проверками и событиями |
| `POST` | `/targets/{id}/checks` | Проверить адрес сейчас |
| `GET` | `/targets/{id}/checks?limit=100` | История проверок, новые сверху |
| `GET` | `/targets/{id}/summary?hours=24` | Сводка проверок за последние N часов |
| `GET` | `/events?limit=100` | Лента событий `up` и `down`, новые сверху |

## Коллекция запросов Bruno

В папке `api/bruno` лежит коллекция для [Bruno](https://www.usebruno.com) с готовыми запросами ко всем эндпоинтам. С ней можно попробовать API, не составляя запросы вручную.

Как пользоваться:

1. Запустите сервис.
2. Откройте в Bruno папку `api/bruno` (Open Collection).
3. Выберите окружение `Local`: в нём указан адрес сервиса `http://localhost:8080`.
4. Выполните запрос «Добавить адрес», а затем любые другие.

Запросы разложены по папкам:

| Папка | Что внутри |
|---|---|
| Служебные | Проверка, что сервис жив |
| Адреса | Добавить, посмотреть, изменить, поставить на паузу, снять с паузы и удалить адрес |
| Проверки | Проверить адрес сейчас, история проверок, сводка за период |
| События | Лента событий падения и восстановления |

Запросы к конкретному адресу используют переменную `targetId`, и заполнять её вручную не нужно: после запроса «Добавить адрес» в неё автоматически записывается `id` нового адреса, и остальные запросы работают с ним.

Чтобы поработать с уже существующим адресом, впишите его `id` в `targetId` окружения `Local` и не вызывайте «Добавить адрес»: этот запрос перезаписывает `targetId` до перезапуска Bruno.

## Запуск в Docker

Файл `.env` нужен так же, как при обычном запуске.

```bash
docker compose up -d --build
```

Остановка:

```bash
docker compose down
```

## Переменные окружения

| Название | По умолчанию | Назначение |
|---|---|---|
| `HTTP_ADDR` | `127.0.0.1:8080` | Адрес и порт HTTP-сервера |
| `DATABASE_URL` | — обязательная | Строка подключения к PostgreSQL |
| `POSTGRES_USER` | — обязательная | Пользователь PostgreSQL в Docker Compose |
| `POSTGRES_PASSWORD` | — обязательная | Пароль PostgreSQL в Docker Compose |
| `POSTGRES_DB` | — обязательная | Имя базы данных в Docker Compose |
| `CHECK_TIMEOUT` | `5s` | Таймаут проверки адреса |
| `SCHEDULER_TICK` | `1s` | Как часто планировщик ищет адреса, которым пора на проверку; не меньше `1s` |
| `CHECK_WORKERS` | `50` | Число одновременных фоновых проверок, от `1` до `1000` |
| `COMPOSE_FILE` | — | Путь к файлу Docker Compose, чтобы команды `docker compose` работали из корня проекта |

Длительности задаются в формате Go: `500ms`, `5s`, `1m`.
